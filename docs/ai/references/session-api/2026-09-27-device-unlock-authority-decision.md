# Paired Device bearers may request target-local desktop entry

Status: accepted authority decision; scope revised on 2026-09-28. The first native release permits paired bearers to unlock **existing locked sessions only**. References below to signed-out sign-in record the earlier broader design and are deferred. The current implementation plan is [locked-session first](2026-09-28-remote-device-entry-implementation-design.md).

## Historical broader-scope decision

Every active paired Device bearer may request that its target Device unlock an existing OS login session or sign in the selected user at a running OS greeter, without a separate grant per caller. The target keeps any OS credential local and verifies the intended session effect. This uses AUV's existing pairing trust boundary: an active paired caller can already create a token that enrolls another Device, and the new bearer receives the same request authority. The owner accepts that remote delegation because paired Devices are intended to connect and administer one another. Disabling, unpairing, or revoking a bearer removes its request authority at the next authentication lookup.

Pairing remains directed. A bearer issued by B authorizes calls to B; it grants B no authority over A. B must pair to A separately before it may request A's unlock. This preserves the current credential and profile model while allowing an explicitly paired network of Devices.

The capability is enabled by default per target Device. A target-local OS administrator may explicitly disable it; paired remote callers cannot change that local setting. Disabling rejects remote entry and read-only OS login-session listing requests but retains enrolled local credentials; an administrator can re-enable the switch without re-enrolling every account. Credential deletion is a separate local operation. While enabled, every active caller paired to the target may request either effect for an OS user enrolled on the target. Each OS user needs target-local enrollment with a stored usable login credential; the default-on machine-wide switch does not itself enroll accounts. A target-local OS administrator may enroll any account, and an ordinary user may enroll their own account. A remote paired administrator cannot use pairing rights to bypass account enrollment. The owner confirmed this account boundary even on GNOME configurations where logind can unlock an existing session without an OS password. Enrollment without a credential cannot enable lock-only remote access.

This decides **who may request** unlock and the target-wide disable switch. It does not decide which user session may be unlocked or how the target stores an OS credential.
