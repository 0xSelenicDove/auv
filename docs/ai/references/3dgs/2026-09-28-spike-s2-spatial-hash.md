## 2. Track A：Projection 标签诚实化

### 2.1 根因剖析与自指涉澄清

在原 `field_test_scenario.rs` 及相关的集成报告中，端到端测试输出包含：
```text
================ FIELD TEST SCENARIO METRICS ================
  recall_success:      true
  projection_error_px: 0.0000 px
  ...
```
并在文档中被描述为"反投影派发点击坐标与真实投影真值完全重合"。

**问题根因**：
- `field_test_scenario.rs` 中，delivered point 是通过 `MinecraftProjector::new(v02_frame)` 投影而来；
- Stage 4 计算所谓"真值"时，再次使用同一个 `MinecraftProjector::new(v02_frame)` 对同一目标方块进行投影，得到 truth point 并计算两者像素差；
- 这本质上是用**同一套代码、同一个矩阵自己算两次**，仅仅验证了模块间参数传递（wiring）未被篡改，是**自洽性检查（Self-consistency Check）**，绝不等于对外界物理世界的**独立投影精度（Independent Projection Accuracy）**。
- 真实的独立测量（见 `tests/projection_accuracy.rs`，以截图瞬间十字准星指准的目标方块为独立基准，消除物理 face center 偏置后）：
  - **v01 帧独立误差**：**21.8px**
  - **v02 帧独立误差**：**60.0px**

### 2.2 改名与规范化落实

1. **统一改名**：
   全仓将 `projection_error_px` 彻底更名为 `projection_self_consistency_px`。
2. **文档与代码注释澄清**：
   在 `field_test_scenario.rs`、`2026-09-27-step5-agent-integration.md` 和 `2026-09-28-step6c-integration.md` 中增加标准化说明：
   > "检查 projector 自洽（同一 projector 算两次），是 wiring 一致性，不是独立精度；独立精度见 2026-09-27 补测：v01 21.8px / v02 60.0px。"
3. **残留扫描**：
   执行 `git grep -n "projection_error_px"`，全仓输出为 0，彻底根除了误导性标签。
4. **回归验证**：
   运行 `cargo test -p auv-game-minecraft --test field_test_scenario`，测试 100% 通过（`projection_self_consistency_px: 0.0000 px`，自洽断言正常工作）。

## 3. Track B：100k Landmark 空间哈希架构设计

### 3.1 核心参数与几何完备性证明

- **去重合并半径**：$R = 0.6\text{ m}$（`dedup_radius_m: 0.6`，欧氏距离米制）。
- **网格划分（Uniform Grid）**：
  网格单元边长设为 cell edge length $L = R = 0.6\text{ m}$。
  对于任意三维点 $p = (x, y, z)$，其离散网格整数坐标为：
  $$ix = \lfloor x / R \rfloor, \quad iy = \lfloor y / R \rfloor, \quad iz = \lfloor z / R \rfloor$$
- **邻域检索范围**：
  检索当前格及各轴方向相邻 $\pm 1$ 的网格，共检查 $3 \times 3 \times 3 = 27$ 个邻居单元格。

#### 完备性数学证明（无漏检保证）
设两点 $P(x_1, y_1, z_1)$ 与 $Q(x_2, y_2, z_2)$ 的欧氏距离 $\text{dist}(P, Q) < R$。  
由欧氏距离定义：
$$(x_1 - x_2)^2 + (y_1 - y_2)^2 + (z_1 - z_2)^2 < R^2 \implies |x_1 - x_2| < R, \; |y_1 - y_2| < R, \; |z_1 - z_2| < R$$
根据下取整函数的数学性质，若两实数差值绝对值 $|x_1 - x_2| < R$，则其对应格网坐标差：
$$|ix_1 - ix_2| = |\lfloor x_1 / R \rfloor - \lfloor x_2 / R \rfloor| \le 1$$
同理，$|iy_1 - iy_2| \le 1$ 且 $|iz_1 - iz_2| \le 1$。  
因此，与查询点 $P$ 距离小于 $R$ 的任意点 $Q$，**必然严格落在 $P$ 所处的 27 个邻居格网之内**，在数学上绝不可能发生漏检。

#### 最坏复杂度常数界证明（$O(1)$ 保证）
由于去重机制规定：任何两颗存入地标之间的距离必然 $\ge R$。  
在边长为 $R$ 的三维立方体内，任意两点距离均 $\ge R$ 的点数上限为常数（密铺极限下至多 8 个角点）。  
因此，27 个相邻格内包含的历史地标数量总和受到几何硬约束限制（理论极限至多 $27 \times 8 = 216$ 个，实际稀疏场景下通常为 0~3 个）。  
因此，无论全局累计存入了 10k 还是 100k 地标，单次去重检测所需计算的距离次数上界恒为 $O(1)$。

---

### 3.2 确定性 Tie-breaking 与 Differential 保证

由于生产 O(N) 线性扫描在遇到第一个满足 $\text{dist} < R$ 的候选时即 `break` 并返回，该行为等价于**选取满足距离条件且插入次序最早（最小索引）的地标**。

为了确保空间哈希原型与 O(N) 线性扫描在任何多重候选场景下行为 100% 等价：
- 空间哈希在扫描 27 个单元格时，检索所有落入该 27 格且满足 $\text{dist} < R$ 的地标候选；
- 选取其中的**最小插入索引**（`best_matching_idx = min(matching_indices)`）；
- 若候选集为空，则创建新地标并将其索引写入对应网格。

这一设计在数学上严格保证了两者在任意点列输入下的状态转移矩阵完全等价。

## 5. 100k 内存开销拆解与量级估算

在 100k 真实写入完成后，对 `UniformGridSpatialHashStore` 各组成部分内存进行精确采样与估算：

| 内存结构部分 | 数据项与容量 | 占用内存 (Bytes) | 占用内存 (MB) | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **HashMap 网格骨架与桶** | 99,993 个格元 (Bucket Overhead) | 7,199,496 B | 6.87 MB | 容量扩容桶开销 (Key 24B + Val 24B + 1B ctrl) |
| **网格内 Vec 堆缓冲区** | 99,993 个 `Vec<usize>` 堆缓冲 | 1,619,992 B | 1.54 MB | 稀疏分布下每格平均容量 1~2 个条目 |
| **网格总开销 (Grid Total)** | — | **8,819,488 B** | **8.41 MB** | **空间哈希索引自身的额外内存** |
| **地标主表 (Landmarks Table)** | 99,993 个 `LandmarkRecord` | 4,799,664 B | 4.58 MB | 基础结构体连续存储空间 |
| **地标字符串 ID 堆内存** | 99,993 个 `String` (`lm-xxxxx`) | 3,329,202 B | 3.17 MB | 动态生成的 ID 字符串 |
| **地标总开销 (Landmark Total)** | — | **8,128,866 B** | **7.75 MB** | 地标基础数据存储 |
| **总体内存占用 (Grand Total)** | **100k 规模** | **16,948,354 B** | **16.16 MB** | **完整占用约 16.2 MB** |

**结论**：
100k 地标仅需 **16.16 MB** 内存。索引层（8.41 MB）与实体存储层（7.75 MB）几乎 1:1，单地标综合开销约 **161 字节**。在单机 Minecraft Agent 环境下，16MB 的内存开销完全微不足道。

   当 `prune_stale()` 触发地标清除时，同步清理 grid 单元格中的对应索引，避免无效条目滞留。
