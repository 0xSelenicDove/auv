### 关键实现点：
1. **内部网格与紧凑槽位**：
   - 生产 `SpatialMemoryStore` 结构体新增私有瞬态索引：
     - `grid: HashMap<CellKey, Vec<usize>>`（CellKey = `(i64, i64, i64)`，网格边长 $R = 0.6\text{m}$）；
     - `slots: Vec<LandmarkSlot>`（记录 `id`, `position`, `is_alive`）；
     - `id_to_slot: HashMap<String, usize>`（用于 O(1) 反查）。
2. **反序列化确定性重建**：
   - `rebuild_grid()` 在 `open_with_config` 与 `set_config`（半径变动）时触发，按 `(captured_at_millis, landmark_id)` 严格确定性排序重构槽位与网格。
3. **27 邻域查询与 Early-Break 对齐**：
   - `find_matching_landmark` 仅检索 $3 \times 3 \times 3 = 27$ 个邻居网格，tie-break 取最小 slot index，严格保持与旧 O(N) 线性扫描插入顺序 early-break 完全一致的语义。
4. **生命周期零幽灵索引保障**：
   - `upsert_from_raycast` & `upsert_from_perception`：新插入地标同步向 slots 和 grid 登记。
   - `upsert_dynamic_landmark`：跨网格移动时先核对新旧坐标网格，若跨格则从 `old_cell` 彻底剔除并在 `new_cell` 登记，杜绝幽灵索引。
   - `prune_stale`：过期/低置信度地标从网格中完全移除（若单元格变空则彻底 `remove(&cell)`），并将对应 slot 标记为 `is_alive = false`。

### 100k 核心指标提速与资源开销：
- **总耗时加速比**：$367,130.45 \text{ ms} / 161.19 \text{ ms} = \mathbf{2,277.7\times}$
- **p95 延迟加速比**：$7,986.60 \text{ µs} / 1.60 \text{ µs} = \mathbf{4,991.6\times}$
- **p95 门禁裁决**：实测 **1.60 µs**（远低于 Brief 要求的 $1.0\text{ ms} = 1,000\text{ µs}$ 门禁）。
- **内存占用实测估计**：
  - 生产网格索引内存：~22.43 MB

  - 100,000 地标总内存：~49.74 MB（完全适于常驻内存）。

  2. `SpatialHashSlotStore`（Candidate A 原型）
  3. `SpatialHashStringStore`（Candidate B 原型）

  - 12% Dynamic Landmark Movement（测试实体跨网格移动时的索引迁移动作）；
  - 10% Record Miss（测试地标置信度衰减）；
  - 8% Prune Stale（推进全局时钟，剔除过期与低置信度地标）。
- **比对结果**：
  - 5,000 步中每一步的插入/合并 ID 返回值四者 **100% 完全相同**；
  - 每次 prune 剔除地标数量四者 **100% 完全相同**；
  - 每 250 步全库中间状态校验全字段 **100% 一致**；
  - 最终全生命周期结束，存活地标（1,051 个）逐个提取，四者所有字段 `assert_eq!` 判定 **100% 完全等价**。

### 4.2 零幽灵索引回归测试
- `test_ghost_index_pruning_and_reinsertion_regression`：验证地标 prune 后网格被彻底清空，在原坐标重新插入时生成全新地标，绝无与幽灵索引错误合并现象。

   - `SpatialMemoryStoreData` 依然仅持久化 `landmarks` 和 `config`，网格索引作为私有瞬态字段不参与 JSON 序列化，完全向前/向后兼容旧版持久化文件。
