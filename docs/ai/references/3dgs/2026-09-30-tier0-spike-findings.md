## 1. 目的与核心问题

在 Step 8 到 Step 11 的验证中，记忆导航的闭环控制依赖模组端遥测（`telemetry.jsonl`）提供的实时玩家位姿（`player_pose`）。虽然感知与入库是纯视觉的，但召回控制事实上处于"开卷考"状态。

本 Spike 的核心目的**不是宣称"已经建成了 Tier-0"**，而是在 Step 8 的基准形态上（单箱子、约 28~30m 远距、纯记忆返回、目标进入 `< 3.5m` 判定到达），在召回阶段**逐级掐掉自身位姿遥测**，做严格的 4 条件消融实验，回答以下三个战略问题：
1. **没了自身位姿遥测，记忆导航还剩几成功力？**
2. **哪块信号是真正承重的？**
3. **如果要补齐黑盒 ego-pose，最小要做什么？未来投不投 Tier-0？**

## 2. 实验设计与隔离红线

### 2.1 阶段划分

- **建图阶段（Ingest）允许使用遥测**：模拟"拿卷尺建地图"（在部署或首次勘测时建立世界坐标系下的 `SpatialLandmark`）。
- **召回阶段（Recall）严格禁止 Agent 读取遥测**：被测的 Tier-0 Agent 只能依赖记忆先验、推测航向、步进盲算（Dead-Reckoning）与视觉目标伺服。
- **外部 Harness 仅用于评分与客观采样**：Harness 读取遥测仅用于记录每 10 个 tick 的真实漂移以及在终点判定真值距离。

### 2.2 代码级防作弊隔离机制

在 `supported/games/auv-game-minecraft/src/bin/tier0_spike.rs` 中，Agent 的上下文 `Tier0AgentContext` 实现了**代码级物理隔离**：
```rust
pub struct Tier0AgentContext {
  condition: TelemetryCondition,
  proprio_pose: EstimatedPose,
  target_pos: (f64, f64, f64),
  detector: Option<BlockDetector>,
  consecutive_turns: usize,
  total_turned_deg: f64,
  last_gps_pos: Option<(f64, f64)>,
}
```
- **结构体内无遥测句柄**：没有 `telemetry_path`、没有 `TelemetryReader`、没有 `MinecraftSpatialFrame` 引用，无法主动或静默偷看遥测文件。
- **构造函数隔离**：`Tier0AgentContext::new()` 仅传入标称起始位姿猜想 `(p1x, p1y, p1z, init_yaw)` 与空间记忆库查询到的目标坐标 `scenario.target_p0`。
- **输入完全受消融门控控制**：Agent 在每 tick 调用的 `step(input)` 中，仅能访问 `AgentPerceptionInput`：
  - `image`：当前第一人称视觉画面；
  - `compass_yaw`：仅在 C0 与 C1 提供；
  - `gps_xz`：仅在 C0 与 C2 提供。
  - 在 **C3** 中，`compass_yaw` 与 `gps_xz` **全部为 `None`**。

### 2.4 口径注记与实验边界（Caveats & Operational Boundaries）

在解读本报告数据与结论前，必须明确以下四项严格的实验边界，不将局部验证过度推演为普适泛化结论：
1. **小样本量探索（Sample Size $n=3$）**：每个消融条件测试 3 组几何场景（S1/S2/S3），共 12 组基线运行 + 3 组校准重跑。本测试是一次量化差距与验证机制的工程 Spike，并非针对全随机地形/极端光照的统计泛化定论。
2. **给定起始位姿的 Recall（Nominal Start Pose Prior）**：Agent 在召回起点被赋予建图时记录的标称起始位姿 $(X_0, Z_0, \text{Yaw}_0)$。测试验证的是"在已知起点位姿下的盲推巡航与视觉终末到达"，**并非未知的绑架机器人问题（Kidnapped-Robot Problem）**。
3. **平原开阔地与固定光照**：测试环境锁定为 Minecraft 超平坦平原（无树木、悬崖或高低起伏障碍），白天恒定锁定（`time set 6000`），排除了动态昼夜、复杂光影退化与视线遮挡。
4. **C0/C1 的航向漂移 $0.0^\circ$ 属于结构设定（By Construction）**：在 C0 和 C1 中，电子罗盘输入直接由 Harness 从底层真实遥测注入，因此航向漂移恒为 $0.0^\circ$ 是实验条件设定的必然结果，而非算法滤波的神迹。

## 4. 关键科学发现与深度归因分析

### 4.1 发现 1：哪块信号是承重的？

1. **航向（Yaw）是第一承重墙（不可或缺的骨架）**：
   - 只要初始航向准确（误差 < 1°），在无侧向颠簸的平原地表，开环前进 30 米的横向偏差只有不到 0.2m。
   - 在 C2（无指南针）中，虽然没有航向遥测，但 Agent 通过**对地航迹推算（Course-Over-Ground, COG）**，在向前迈出前两步（位移 > 0.4m）后立即通过 $\text{atan2}(-\Delta X, \Delta Z)$ 锚定了航向，航向漂移仅仅为 $0.002^\circ \sim 0.005^\circ$，因此 C2 依然能做到 100% 召回。
2. **位置（Position）不是承重墙，可被视觉伺服与开环死算轻易代偿**：
   - C0 与 C1/C3 的对比表明，即便没有任何绝对 GPS 坐标输入，在 30 米射程内，基于恒定移动速率（$4.317\text{ m/s}$）的本体感觉积分误差不超过 1.2m。
3. **视觉闭环（Visual Servoing）是消除累积误差的终末制导门禁**：
   - 当 Agent 前进到目标 8 米以内时，YOLOv8n v2 模型检出箱子（置信度 0.65~0.82）。
   - 视觉伺服将箱子水平中心偏差（`offset_deg`）收敛至 0°，并根据视觉成像尺寸直接判定接近距离，完全消除了前段开环死算的残差。

### 4.2 发现 2：为什么 C1 失败（DriftLost），而 C3 最终由视觉门禁成功到站？

这是一个**极其反直觉但极其深刻的物理事实**：
- **C1 Run 2 真实死因剖析**：
  在 S2 对角线场景中，Agent 拥有准确的指南针 Yaw（-49.0°），通过标称步速（4.317 m/s）估算前进位移。然而在 Minecraft 中，斜向移动的有效速度受键盘输入与浮点摩擦衰减影响仅约 ~4.1 m/s（存在约 5% 的尺度高估）。经过 26 米长跑，盲推累积了 **1.16m** 的纵向尺度漂移。
  在第 20 tick 时，Agent 内部死算显示距离已达 **2.63m**，触碰了初版代码中的 `< 2.8m` 停步逻辑。Agent 误以为自己已到站而发出 `StopSuccess`。然而真实距离仍为 **3.79m**（超出 3.50m 阈值 0.29m），被 Harness 判为经典的 `DriftLost`。
  *结论*：**开环死算的时间积分尺度漂移是真实且致命的失败模式；死算距离绝不能作为到站早停分支！**
- **初版 C3 的伪闭环与归因缺漏**：
  在初版 12 Runs 测试中，C3 虽然数字上全部达标，但终点距离均落在 `(2.8m, 3.5m)` 区间。经代码审计揭示，这实际上被 Harness 侧的 `cur_true_dist < 3.50` 自动截胡，Agent 侧的视觉到达与距离停步分支一次都未被真实行使，初版报告中的"198px 触发停步"缺乏单 run 产物证据支持。
- **Option A 校准重跑的真实硬核证据（C3 Calibrated）**：
  在彻底删除 Harness Auto-Pass 截胡并严禁 `est_dist < 2.8` 参与视觉伺服分支后，真正将终末到站决策交给 Agent 自身：
  1. **S1 (直线正南)**：Tick 19 视野中宝箱高度达到 **163.0px**（> 160px 门禁），Agent 主动以 `AgentVisualBbox` 停步，真实距离精准定格在 **2.55m**；
  2. **S2 (东南对角)**：Tick 19 视野中宝箱高度为 148.1px（未满 160px）。因为剔除了盲算早停分支，Agent 未像 C1 那样在 3.79m 处早停，而是继续小步迈进；在 Tick 21 死算兜底达到 1.99m 叫停，真实距离定格在 **2.01m**，稳稳落入目标区；
  3. **S3 (西北对角)**：Tick 19 视野中宝箱高度达到 **197.4px**（> 160px 门禁），Agent 主动以 `AgentVisualBbox` 停步，真实距离精准定格在 **2.90m**。
- **核心科学结论**：
  1. 巡航段的开环死算足以把 Agent 从 30m 外带入 8m 视觉捕获区（横向误差 < 0.2m）；
  2. 到达段必须由目标物体在视网膜上的**物理投影尺寸（BBox 高度）**执行单调物理门禁（> 160px），代偿开环死算的纵向尺度误差，真正由 Agent 自主完成终末到达。

### 4.3 发现 3：漂移随时间/距离的演化特征

从 10-tick 的抽样数据（见下表）可以清晰看出漂移的演化规律：

| 采样阶段 | 典型真实剩余距离 | C1 平均位置漂移 | C3 平均位置漂移 | 航向漂移 |
|---|---|---|---|---|
| **Tick 1 (起点)** | 28.0m ~ 30.5m | 0.00m | 0.00m | < 0.01° |
| **Tick 10 (中途)** | 14.5m ~ 18.0m | 0.54m | 0.40m | < 0.01° |
| **Tick 20 (终点)** | 2.87m ~ 3.79m | 0.47m (最大 1.16m) | 0.24m (最大 0.41m) | < 0.01° |

- **平地前进漂移是有界的**：在 30 米平原直行中，位置漂移主要来自**沿运动轴线的纵向尺度误差（Longitudinal Scale Error）**，横向侧偏几乎为零。
- **航向无漂移假象**：在没有鼠标旋转指令时，Minecraft 的内部视角朝向完全不会自发漂移。因此在 C3 中，航向漂移始终保持在 $0.01^\circ$ 以内。

## 5. 补齐黑盒 Ego-Pose 最小要做什么？

如果要摆脱平原开阔地的简单假设，在真实复杂非结构化环境做**真 Tier-0**，最小系统需求是什么？

### 5.1 方案对比分析

| **A. 传统稠密 3D Visual SLAM (如 ORB-SLAM3)** | 极高 (C++ FFI / 特征点 / BA 优化) | 高 (>50ms/帧，易丢帧) | 输出 6-DoF 绝对轨迹，但在纹理缺失时易退化崩溃 | **NO-GO**（重型、过载、易断裂） |
| **B. 稠密深度 + 3DGS 地图回环** | 极高 (显存消耗大、训练不可泛化) | 秒级 | 2026-09-25 已证明稀疏视角不泛化 (Slice B Closeout) | **NO-GO**（已淘汰路线） |
| **C. 轻量级光流 / 稀疏视觉里程计 (VO / Optical Flow)** | 中等 (OpenCV Farneback / Lucas-Kanade) | 低 (10~15ms/帧) | 消除沿途步长积分偏差，提供准确的前进速度与位移比例尺 | **候选第二阶段 (Candidate Next)** |
| **D. 航向保持 + 死算粗巡航 + 终末视觉伺服 (Coarse Nav + Visual Servo)** | **极低 (零外部库，纯利用现有 YOLO v2)** | **极低 (<5ms)** | **航向由初始先验锁定，中途死算粗定位至 8m 视锥，近程交由视觉检测闭环接管** | **GO (推荐基线)** |

### 5.2 最小可行落地规格（The Minimum Viable Tier-0 Recipe）

如果确认要推进 Tier-0，不要做重型 SLAM，最小做以下两件事即可跑通复杂场景：
1. **视觉航向锚定（Sky / Horizon Optical Heading or Sun Compass）**：
   通过视野上方天际线、太阳或地平面特征流，保证转向后无漂移，无需读取任何指南针遥测。
2. **纯视觉到达门禁（Visual-Only Arrival Gating）**：
   严禁使用 `est_dist < 阈值` 停步。只要进入目标搜索半径，必须在第一人称画面检出目标物体，且当目标 Bounding Box 像素高度达到几何标定尺寸（例如 480p 下宝箱高度 $> 160\text{px}$ 代表距离 $< 2.9\text{m}$）时才准停步。若扑空未见，则进入螺旋/扇形视场搜索，杜绝 `DriftLost`。

## 6. 最终裁决与投资建议（GO / NO-GO Verdict）

### 裁决结论：**GO (针对轻量级视觉伺服闭环) / NO-GO (针对重型视觉 SLAM 投资)**

1. **对继续深化"死算粗巡航 + 终末视觉闭环"：明确给出 GO**
   - 本次 Spike 用硬数据证明：**在 $n=3$、平原开阔地、给定起始位姿先验的基准条件下，纯靠死算粗导航（覆盖前 20+ 米）+ YOLO 终末视觉到达门禁（解决最后 5~8 米并主导到站），在掐断全部遥测（C3）下实现 3/3 达标，平均到达真值距离达到 2.48m，且 S1/S3 均由 163px / 197px 纯视觉门禁自主触发停步**。
   - 这意味着在受限场景下，AUV 并不依赖庞大的 SLAM 算法堆栈即可完成开环到闭环的交接。
   - **后续建议投入**：重点打磨终末视觉到达门禁（多尺度标定、目标短暂丢失时的局部搜索扇面、地平线/太阳粗航向锚定），将这套轻量视觉伺服硬件真正做实做强。
2. **对引入大型 3D Visual SLAM / 稠密网格建图：明确给出 NO-GO**
   - 现有的轻量级几何与 YOLO-World/YOLOv8 闭集模型已经在 Step 8~11 建立起坚固的 `SpatialMemoryStore`。
   - 把资源投向重型 3D SLAM 不仅会大幅增加依赖膨胀与工程脆弱性，而且对 AUV 的核心使命（指令级、可重放、高精度的 UI/工作流操作）毫无性价比。
