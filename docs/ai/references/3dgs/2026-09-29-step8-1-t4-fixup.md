# Step 8.1 T4 时序修复 + 重跑验收报告

状态：**PASS** — 2026-09-29 实机验证通过，箱子 GUI 已打开。

## 1. 问题归因（T-F0）

Step 8（d10d2f31）T4 未能打开箱子 GUI，原因如下：

| 问题点 | Step 8 的行为 | 证据 |
|--------|---------------|------|
| settle 时间不足 | turn_mouse 后只等 200ms 就发右键 | T4 log：`aim_pitch_delta=49.0°`，pitch 远未稳定 |
| 仅单次尝试 | 无 retry 逻辑，失败即放弃 | 报告：`retry_attempts` 字段不存在 |
| Telemetry 不刷新 | 整个 T4 只读一次 telemetry，之后不重读 | 即使 turn_mouse 发出后 pitch 已更新，代码仍用旧数据计算 |
| pitch 目标计算误差 | 用 `target_pos.1 - eye.y`（记忆坐标 y）而非 `block_pos.y + 0.5` | chest center y=94.5 vs 记忆 y=94.52，误差可忽略但公式不清晰 |

**根本原因**：`SendInput MOUSEEVENTF_MOVE` 被 GLFW 异步处理（约 1 game tick ≈ 50ms），
200ms 等待在有些帧时序下不够。第 1、2 次 retry 的 telemetry 显示 pitch 仍为 0.0°（未更新），
直到第 3 次 retry 才读到 pitch=21.8°，瞄准误差降至 -0.1°，右键命中。


### 改动三：turn_mouse 后等待 500ms
```rust
// NOTICE: SendInput MOUSEEVENTF_MOVE is applied asynchronously by the GLFW input loop;
// Minecraft processes it within ~1 game tick (~50ms).
// We wait 500ms to ensure the view has fully settled before dispatching the click.

```

### 改动四：`T4AttemptRecord` 结构体记录每次 retry 的详细数据
