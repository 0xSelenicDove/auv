# Skill token correction: registered model-session benchmark

Registered before trial 01, 2026-10-08. Four fresh isolated sessions:
current skill/A, revised skill/A, revised skill/B, current skill/B.
Both arms use the identical f9abd0e5 release binary, hash in manifest.
Baseline skill is frozen from dfa4abee; candidate skill hashes frozen in manifest.
No runtime, skill or prompt edits during measurement. Same two eight-record
cases, starting top viewport, foreground uncovered synthetic 180-row canvas,
gpt-5.6-sol low, Codex CLI 0.150.1, 900-second timeout. Task prompts from the
prior pilot differ only in binary, skill and scratch paths. No extra advice
about the intended answer or preferred strategy is supplied to the subjects.

Measure verified success, provider input+output including cached input once,
and elapsed time from model launch through exit. Include discovery, help/skill
reading, daemon startup if chosen, recovery and screenshot verification.
Setup/reset, independent OCR audit and teardown after exit are outside timing.
All trials run sequentially; no prestarted daemon is supplied. Preserve failures
and partial outcomes without replacement or pooling with earlier pilots.
No production builds or independent OCR audits during measured sessions.

Audit withheld oracle triples, full rows on original saved images, original
artifact hashes, and an independent final-window screenshot. Image inspection
is a subject claim because the CLI JSON stream does not expose image-view tool
calls independently. Equal verified completion is required for savings claims.
Two cases remain a small synthetic pilot: model strategy, backend route, image
sizes and OS state can vary. No native or without-skill arms in this comparison.
Temporary authentication copies are removed at exit and excluded from evidence.
No permissions, other-app access, installations or extra agents are authorized
inside subjects. Frozen binary/skill hashes are rechecked after completion.
